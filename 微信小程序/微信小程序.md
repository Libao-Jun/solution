## 一、小程序的本质

### 1.1 三个核心判断

| 维度     | 说明                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 运行环境 | 不是浏览器。iOS 运行在 JavaScriptCore，Android 运行在 V8，开发者工具运行在 NW.js。**没有 `window` / `document` / DOM / BOM** |
| 渲染架构 | **双线程模型**：逻辑层（AppService）与视图层（WebView / Skyline）分离，通过 Native 层中转通信                                |
| 获取方式 | 无需安装，微信内扫码 / 搜索 / 分享 / 公众号菜单等入口打开                                                                    |

### 1.2 与普通网页开发的区别（面试与踩坑高频）

1. **不能使用 DOM API**：`document.getElementById`、`innerHTML`、`window.location` 全部不可用；`window` 对象也不存在（有 `wx` 全局对象）。
2. **没有 `cookie`**：登录态需要自己维护（通常用 `wx.setStorageSync` 存自定义 token）。
3. **不能直接跳转外链**：`window.open` 不存在，外部网页必须用 `<web-view>` 组件且域名需在后台配置为业务域名。
4. **网络请求走 `wx.request`**：不是 `XMLHttpRequest` / `fetch`（部分场景下框架会 polyfill，但应以 `wx.request` 为准）。
5. **样式隔离与选择器受限**：WXSS 只支持部分 CSS 选择器（见 [八](#八wxml--wxss--wxs-要点)）。
6. **包体有硬性上限**：主包 / 单个分包 ≤ 2MB，这是架构设计的第一约束。
7. **代码需审核**：发布前必须通过微信审核，涉及类目资质、隐私协议、内容安全。

### 1.3 两类渲染引擎

| 引擎                | 说明                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| **WebView**（默认） | 兼容性最好，历史悠久，组件与样式支持最全                                                          |
| **Skyline**         | 新一代渲染引擎，性能更好（自定义路由、Worklet 动画、共享元素动画），但对部分 CSS / 组件支持有差异 |

> ⚠️ **选型坑**：老项目迁 Skyline 需逐个页面验证，`position: fixed`、`overflow`、部分 CSS 选择器行为不同。官方提供了迁移工具，但务必做全量回归。

## 二、从 0 到 1：账号申请与环境搭建

### 2.1 完整流程

```text
① 注册账号       mp.weixin.qq.com → 立即注册 → 选择「小程序」
                 （个人 / 企业 / 政府 / 媒体 / 其他组织）
      ↓
② 填写主体信息   个人主体：身份证 + 微信扫码验证
                 企业主体：营业执照 + 对公打款验证或微信认证（300元/年）
      ↓
③ 完善小程序信息 名称（唯一，一年可改 2 次）、头像、简介、服务类目
      ↓
④ 获取 AppID     后台 → 开发 → 开发设置 → AppID(小程序ID)
      ↓
⑤ 安装开发者工具 https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
      ↓
⑥ 创建项目       工具中填入 AppID，选择「不使用云服务」或「小程序·云开发」
      ↓
⑦ 编译预览       工具内模拟器 / 点「预览」扫码真机体验
```

### 2.2 关键 ID 与密钥（务必分清）

| 名称                  | 位置                                      | 用途                                               | 能否放前端                     |
| --------------------- | ----------------------------------------- | -------------------------------------------------- | ------------------------------ |
| **AppID**             | 后台 → 开发设置                           | 小程序唯一标识，公开                               | ✅ 可以                        |
| **AppSecret**         | 后台 → 开发设置（只显示一次，需自行保存） | 调用 `code2Session`、`getAccessToken` 等服务端接口 | ❌ **绝对不能**                |
| **商户号 mchid**      | 微信支付商户平台                          | 微信支付                                           | ❌ 不能                        |
| **商户 API 证书私钥** | 商户平台下载 `apiclient_key.pem`          | APIv3 请求签名                                     | ❌ 不能                        |
| **OpenID**            | 服务端换取                                | 用户在**本小程序**下的唯一 ID                      | 前端可持有（配合自己的登录态） |
| **UnionID**           | 服务端换取                                | 用户在**同一开放平台账号**下的唯一 ID              | 前端可持有                     |

> 🔥 **头号安全坑**：把 AppSecret / 商户私钥写进小程序前端代码，等于把整个账号交出去。任何需要 AppSecret 的调用（`code2Session`、发送订阅消息、获取 `access_token`）**必须在服务端完成**。

### 2.3 重要后台配置项

| 配置         | 路径                                   | 说明                                                                           |
| ------------ | -------------------------------------- | ------------------------------------------------------------------------------ |
| 服务器域名   | 开发 → 开发设置 → 服务器域名           | request / uploadFile / downloadFile / socket 四类，**必须 HTTPS + ICP 备案**   |
| 业务域名     | 开发 → 开发设置 → 业务域名             | `<web-view>` 可加载的域名，需下载校验文件放到域名根目录                        |
| 消息推送     | 开发 → 开发设置 → 消息推送             | 客服消息、支付回调等服务端事件                                                 |
| 类目         | 设置 → 基本设置 → 服务类目             | 决定可用能力（如支付、手机号、直播），**选错类目会导致审核被拒**               |
| 隐私保护指引 | 设置 → 服务内容声明 → 用户隐私保护指引 | 2023 年起强制，未配置会导致 `getUserProfile`、`getLocation` 等接口**直接失败** |
| 成员管理     | 管理 → 成员管理                        | 项目成员（运营者/开发者/数据分析者）与体验成员                                 |

> ⚠️ **隐私保护指引坑**：这是 2023 年后最高频的"接口突然失效"原因。需在 `app.json` 配置 `__usePrivacyCheck__` 并使用 `wx.requirePrivacyAuthorize`，详见 [官方隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

## 三、代码构成与目录结构

### 3.1 四种文件类型

| 后缀    | 角色     | 类比       |
| ------- | -------- | ---------- |
| `.json` | 静态配置 | 配置文件   |
| `.wxml` | 页面结构 | HTML       |
| `.wxss` | 样式     | CSS        |
| `.js`   | 逻辑交互 | JavaScript |

### 3.2 典型目录结构

```text
├── app.js                 # 小程序入口逻辑（App 实例，全局唯一）
├── app.json               # 全局配置（页面路径、窗口、tabBar、分包、权限声明…）
├── app.wxss               # 全局样式
├── project.config.json    # 开发者工具个性化配置（换机器可恢复）
├── project.private.config.json  # 个人配置（应加入 .gitignore）
├── sitemap.json           # 索引配置（控制页面能否被微信搜索收录）
├── pages/
│   └── index/
│       ├── index.js
│       ├── index.json     # 页面配置（优先级高于 app.json 的 window）
│       ├── index.wxml
│       └── index.wxss
├── components/            # 自定义组件
│   └── my-card/
│       ├── my-card.js
│       ├── my-card.json   # 必须声明 "component": true
│       ├── my-card.wxml
│       └── my-card.wxss
├── utils/
│   └── request.js         # 封装 wx.request
├── packageA/              # 分包
│   └── pages/...
└── images/                # 静态资源（注意：会打包进代码包，尽量用 CDN）
```

> ⚠️ **坑**：`pages/index/index` 四个文件缺一不可（`.json` 可省略，框架会兜底，但 `.js`/`.wxml` 必须有）。页面路径写错是"白屏"第一原因。

### 3.3 JSON 语法硬性约束（新手高频报错源）

1. **Key 必须用双引号包裹**，单引号或不加引号会报错。
2. **不能写注释**（`//` 或 `/* */` 都会报错）。
3. 值只能是：数字、字符串、布尔、数组、对象、`null`。**不能有 `undefined`、函数、变量**。
4. **不能有尾随逗号**（最后一个元素后不能有 `,`）。
5. 开发者工具会对 `app.json` 做校验，但自定义 JSON（如自己写的配置）需要自己保证合法。

### 3.4 sitemap.json

```json
{
  "desc": "关于本文件的更多信息，请参考文档 https://developers.weixin.qq.com/miniprogram/dev/framework/sitemap.html",
  "rules": [
    {
      "action": "allow",
      "page": "*"
    }
  ]
}
```

默认 `action: "allow"` 表示所有页面可被微信搜索收录；设为 `"disallow"` 可屏蔽。也可在 `app.json` 中 `"sitemapLocation": "sitemap.json"` 指定。

## 四、全局配置 app.json 全解析

### 4.1 完整示例

```json
{
  "pages": ["pages/index/index", "pages/mine/mine"],
  "window": {
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTextStyle": "black",
    "navigationBarTitleText": "我的小程序",
    "backgroundColor": "#f5f5f5",
    "backgroundTextStyle": "light",
    "enablePullDownRefresh": false,
    "onReachBottomDistance": 50
  },
  "tabBar": {
    "color": "#999999",
    "selectedColor": "#07c160",
    "backgroundColor": "#ffffff",
    "borderStyle": "black",
    "custom": false,
    "list": [
      {
        "pagePath": "pages/index/index",
        "text": "首页",
        "iconPath": "images/home.png",
        "selectedIconPath": "images/home_on.png"
      },
      {
        "pagePath": "pages/mine/mine",
        "text": "我的",
        "iconPath": "images/mine.png",
        "selectedIconPath": "images/mine_on.png"
      }
    ]
  },
  "networkTimeout": {
    "request": 10000,
    "connectSocket": 10000,
    "uploadFile": 10000,
    "downloadFile": 10000
  },
  "permission": {
    "scope.userLocation": {
      "desc": "用于展示附近的门店"
    }
  },
  "requiredPrivateInfos": ["getLocation", "chooseLocation"],
  "requiredBackgroundModes": ["audio", "location"],
  "lazyCodeLoading": "requiredComponents",
  "debug": false,
  "sitemapLocation": "sitemap.json",
  "subPackages": [],
  "preloadRule": {},
  "usingComponents": {},
  "darkmode": true,
  "themeLocation": "theme.json"
}
```

### 4.2 关键字段与坑

| 字段                                 | 说明                                      | 坑点                                                                                              |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `pages`                              | 所有页面路径数组                          | **第一项就是首页**；不写在这里的页面无法跳转                                                      |
| `window`                             | 全局窗口表现                              | 页面级 `.json` 同名配置会覆盖它                                                                   |
| `tabBar.list`                        | tab 配置                                  | **最少 2 个、最多 5 个**；`pagePath` 必须在 `pages` 中；**tabBar 页面必须在主包内**（不能在分包） |
| `permission.scope.userLocation.desc` | 地理位置用途说明                          | **不配置则位置授权弹窗不出现**，接口直接失败                                                      |
| `requiredPrivateInfos`               | 声明使用的隐私接口                        | 未声明的隐私接口调用会失败                                                                        |
| `requiredBackgroundModes`            | 后台运行能力（audio/location/bluetooth…） | 后台定位必须声明                                                                                  |
| `lazyCodeLoading`                    | `"requiredComponents"` 开启按需注入       | 强烈建议开启，可显著优化启动性能                                                                  |
| `networkTimeout`                     | 默认 60s                                  | `wx.request` 的 `timeout` 参数优先级更高                                                          |
| `darkmode`                           | 深色模式                                  | 需配合 `theme.json`，且要处理 `theme` 变量                                                        |
| `__usePrivacyCheck__`                | 开启隐私协议校验                          | 涉及用户信息/位置等接口必须开启并适配                                                             |

### 4.3 页面配置（page.json）

页面级 `.json` 只支持 `window` 相关字段 + `usingComponents` + `enablePullDownRefresh` + `disableScroll` 等，**不能配置 `pages`、`tabBar`、`subPackages`**。

> ⚠️ **坑**：页面 `.json` 里写 `pages` 或 `tabBar` 不生效且不报错，容易浪费时间排查。

## 五、框架与运行时机制

### 5.1 双线程模型

```text
┌─────────────────────────┐         ┌─────────────────────────┐
│      视图层 (View)       │         │    逻辑层 (AppService)   │
│  WebView / Skyline      │         │  JSCore / V8            │
│  WXML + WXSS            │◄───────►│  JS (App / Page)        │
│  多个页面 = 多个 WebView │  Native │  单线程，全局唯一 App    │
└─────────────────────────┘  中转   └─────────────────────────┘
                    ▲
                    │
            ┌───────┴────────┐
            │  Native (微信)  │
            │  转发/API 能力  │
            └────────────────┘
```

**关键推论（必考）**：

- 逻辑层与视图层**通信是异步的**，通过 Native 中转，`setData` 不是同步生效。
- 视图层**拿不到逻辑层的 JS 变量**，只能通过 `setData` 传数据。
- 逻辑层**不能操作 DOM**（它根本不在同一个上下文）。

### 5.2 启动方式

| 类型       | 触发条件                            | 生命周期              |
| ---------- | ----------------------------------- | --------------------- |
| **冷启动** | 首次打开，或小程序被销毁后再次打开  | `onLaunch` + `onShow` |
| **热启动** | 小程序在后台（约 5 分钟内）再次打开 | 只有 `onShow`         |

> ⚠️ **坑**：依赖 `onLaunch` 做一次性初始化（如获取用户信息）在热启动时不会执行。需要"每次进入都刷新"的逻辑必须放 `onShow`。

### 5.3 更新机制

小程序更新是异步的，微信会在**冷启动**时检查更新（24 小时内若检查过则不再检查）。可用 `wx.getUpdateManager()` 主动提示用户重启：

```js
// app.js
App({
  onLaunch() {
    if (!wx.canIUse("getUpdateManager")) return;
    const updateManager = wx.getUpdateManager();
    updateManager.onCheckForUpdate((res) => {
      console.log("是否有新版本：", res.hasUpdate);
    });
    updateManager.onUpdateReady(() => {
      wx.showModal({
        title: "更新提示",
        content: "新版本已经准备好，是否重启应用？",
        success(res) {
          if (res.confirm) updateManager.applyUpdate();
        },
      });
    });
    updateManager.onUpdateFailed(() => {
      wx.showToast({ title: "更新失败，请删除小程序后重新搜索", icon: "none" });
    });
  },
});
```

> ⚠️ **坑**：用户在开发者工具里点"编译"看不到这个效果，只有真机 + 上一版本才能测。新版本通常在**第二天**才对所有用户生效。

## 六、生命周期全解析

### 6.1 App 生命周期（`app.js`）

| 生命周期                    | 触发时机                   | 次数            | 参数                         |
| --------------------------- | -------------------------- | --------------- | ---------------------------- |
| `onLaunch(options)`         | 小程序初始化完成（冷启动） | **全局仅 1 次** | 启动参数                     |
| `onShow(options)`           | 启动，或从后台切回前台     | 多次            | 启动参数                     |
| `onHide()`                  | 从前台进入后台             | 多次            | 无                           |
| `onError(error)`            | JS 脚本错误或 API 调用报错 | 多次            | 错误字符串                   |
| `onPageNotFound(obj)`       | 要打开的页面不存在         | 多次            | `{path, query, isEntryPage}` |
| `onUnhandledRejection(obj)` | 未处理的 Promise reject    | 多次            | `{reason, promise}`          |
| `onThemeChange(obj)`        | 系统主题变化               | 多次            | `{theme: 'light'\|'dark'}`   |

`options` 常用字段：`path`（启动路径）、`query`（启动参数）、`scene`（**场景值**，如 1001 主入口、1007 好友分享、1011 扫码）、`shareTicket`、`referrerInfo`（来源小程序 appId）。

### 6.2 Page 生命周期

| 生命周期                    | 触发时机                                          | 次数        |
| --------------------------- | ------------------------------------------------- | ----------- |
| `onLoad(options)`           | 页面加载，可拿到路由参数                          | **仅 1 次** |
| `onShow()`                  | 页面显示（含从其他页返回、后台回前台）            | 多次        |
| `onReady()`                 | 页面**首次渲染完成**                              | **仅 1 次** |
| `onHide()`                  | 页面隐藏（navigateTo / switchTab / 小程序进后台） | 多次        |
| `onUnload()`                | 页面卸载（redirectTo / navigateBack / reLaunch）  | **仅 1 次** |
| `onPullDownRefresh()`       | 下拉刷新（需 `enablePullDownRefresh: true`）      | 多次        |
| `onReachBottom()`           | 触底（默认距底 50px）                             | 多次        |
| `onPageScroll({scrollTop})` | 页面滚动                                          | **高频**    |
| `onShareAppMessage()`       | 用户点转发 / `button open-type="share"`           | 多次        |
| `onShareTimeline()`         | 分享到朋友圈（需定义才有入口）                    | 多次        |
| `onAddToFavorites()`        | 用户点收藏                                        | 多次        |
| `onResize()`                | 屏幕旋转 / 显示区域变化                           | 多次        |
| `onTabItemTap(item)`        | 点击当前 tab                                      | 多次        |

### 6.3 执行顺序（必记）

**冷启动：**

```text
App.onLaunch → App.onShow → Page.onLoad → Page.onShow → Page.onReady
```

**热启动（后台回前台）：**

```text
App.onShow → Page.onShow
```

**进后台 / 回前台：**

```text
进入后台：Page.onHide → App.onHide
回到前台：App.onShow  → Page.onShow
```

**页面跳转：**

| 方式           | 顺序                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| `navigateTo`   | 旧页 `onHide` → 新页 `onLoad` → `onShow` → `onReady`                         |
| `navigateBack` | 当前页 `onUnload` → 上一页 `onShow`                                          |
| `redirectTo`   | 旧页 `onUnload` → 新页 `onLoad` → `onShow` → `onReady`                       |
| `reLaunch`     | 所有页 `onUnload` → 新页 `onLoad` → `onShow` → `onReady`                     |
| `switchTab`    | 非 tab 页 `onUnload`；目标 tab 首次 `onLoad/onShow/onReady`，再次仅 `onShow` |

### 6.4 组件生命周期（`Component`）

```js
Component({
  lifetimes: {
    created() {}, // 实例创建，不能 setData
    attached() {}, // 进入页面节点树，可 setData
    ready() {}, // 布局完成
    moved() {},
    detached() {}, // 被移除，**必须在这里清理定时器/监听**
    error() {},
  },
  pageLifetimes: {
    show() {}, // 所在页面 onShow
    hide() {},
    resize() {},
  },
});
```

> 🔥 **经典坑（内存泄漏）**：在 `attached` 里 `setInterval` / `wx.onXxx` 注册监听，却没在 `detached` 里清理 → 页面反复进出后定时器/监听累积，内存暴涨、数据错乱。**所有副作用必须在 `detached` 中对称清理**。

### 6.5 实践建议

1. 需要"每次回前台刷新"的写 `onShow`；只做一次初始化的写 `onLaunch` / `onLoad`。
2. `createSelectorQuery` / `createIntersectionObserver` 必须在 `onReady` 之后调用，`onLoad` 时渲染未完成拿不到节点。
3. `onError` + `onUnhandledRejection` 做全局错误上报。
4. `onPageNotFound` 兜底失效路由（老分享链接失效时重定向到首页）。
5. `onPageScroll` 里禁止 `setData` 或做重计算（高频触发）。

## 七、路由与页面栈

### 7.1 五种跳转 API

| API                        | 行为                 | 页面栈                 | tabBar 页     |
| -------------------------- | -------------------- | ---------------------- | ------------- |
| `wx.navigateTo`            | 保留当前页，打开新页 | 入栈（**最多 10 层**） | ❌ 不能跳     |
| `wx.redirectTo`            | 关闭当前页，打开新页 | 替换栈顶               | ❌ 不能跳     |
| `wx.switchTab`             | 切到 tabBar 页面     | 清空非 tab 页          | ✅ 只能跳 tab |
| `wx.reLaunch`              | 关闭所有页，打开新页 | 清空                   | ✅ 可以       |
| `wx.navigateBack({delta})` | 返回上 N 页          | 出栈                   | ✅            |

### 7.2 传参

```js
// 跳转
wx.navigateTo({
  url: "/pages/detail/detail?id=123&from=share",
  events: {
    // 被打开页面通过 eventChannel.emit 回调
    acceptData(data) {
      console.log(data);
    },
  },
  success(res) {
    res.eventChannel.emit("sendData", { foo: "bar" });
  },
});

// 目标页接收
Page({
  onLoad(options) {
    console.log(options.id, options.from); // '123' 'share' —— 注意：全是字符串
    const ec = this.getOpenerEventChannel();
    ec.on("sendData", (data) => console.log(data));
    ec.emit("acceptData", { back: true });
  },
});
```

### 7.3 坑点清单

1. **`navigateTo` 最多 10 层**，超限会 `fail: webview count limit exceed`。深层跳转应改用 `redirectTo` 或 `reLaunch`。
2. **URL 参数全部是字符串**，`?id=123` 拿到的 `options.id === '123'`。
3. **`switchTab` 不能带参数**（url 后不能跟 `?`），跨 tab 传值要用全局变量 / storage / eventChannel（reLaunch 可带参）。
4. **路径写法**：以 `/` 开头为绝对路径（推荐），否则相对当前页面。
5. `navigateBack` 到不存在的层级会失败，可用 `getCurrentPages().length` 判断。
6. `wx.navigateBack` 后上一页的 `onLoad` **不会**再次触发，需要刷新数据要写在 `onShow`。

## 八、WXML / WXSS / WXS 要点

### 8.1 数据绑定与指令

```html
<!-- 数据绑定 -->
<view>{{ message }}</view>
<view>{{ user.name }} - {{ list[0] }}</view>
<!-- 支持简单运算与三元 -->
<view>{{ a + b }} - {{ flag ? '是' : '否' }}</view>

<!-- 条件渲染 -->
<view wx:if="{{type === 1}}">A</view>
<view wx:elif="{{type === 2}}">B</view>
<view wx:else>C</view>

<!-- 列表渲染 -->
<view wx:for="{{list}}" wx:key="id" wx:for-item="item" wx:for-index="idx">
  {{idx}}: {{item.name}}
</view>
```

### 8.2 `wx:key`（性能与正确性关键）

- 必须用 `wx:key`，否则列表更新时**整个列表重渲染**，且输入框内容/组件状态会错乱。
- 写法：`wx:key="id"`（item 的唯一属性名）或 `wx:key="*this"`（item 本身是唯一字符串/数字）。

> 🔥 **坑**：不写 `wx:key` 开发工具只给警告不报错，但会出现"列表数据变了但视图不更新 / 输入框内容串位"的诡异 bug。

### 8.3 `wx:if` vs `hidden`

| 对比 | `wx:if`         | `hidden`           |
| ---- | --------------- | ------------------ |
| 机制 | 销毁 / 重建节点 | 仅 `display: none` |
| 开销 | 切换开销大      | 初始渲染开销大     |
| 适用 | 条件很少变化    | 频繁切换           |

### 8.4 WXSS 要点

1. **尺寸单位 `rpx`**：规定屏幕宽为 750rpx。`iPhone 6` 上 1rpx = 0.5px = 1 物理像素。**设计稿按 750px 宽出图，量多少写多少 rpx**。
   - ⚠️ 坑：`rpx` 是浮点换算，会有微小偏差；**1px 边框不要用 rpx**（可能变粗/消失），直接写 `1px`。
   - ⚠️ 坑：`font-size` 用 rpx 会在大屏上异常放大，字号建议用 `px`。
2. **样式作用域**：`app.wxss` 全局，`page.wxss` 局部（**只对该页面生效，包括该页面内的组件节点**）。
3. **支持的选择器有限**：`.class`、`#id`、`element`、`element,element`、`::before`、`::after`、子代等。**不支持**通配符 `*`、属性选择器（部分版本）、复杂后代选择器（部分版本）。
4. **组件样式隔离**：默认 `styleIsolation: 'isolated'`，组件内外样式互不影响；可用 `externalClasses` 或 `styleIsolation: 'apply-shared'` 打破。
5. `@import` 可引入外部样式，路径需相对。
6. **本地资源**：WXSS 中 `background-image` **不能用本地图片路径**（必须用网络图或 base64），但 `<image src>` 可以。

### 8.5 WXS（视图层脚本）

```html
<wxs module="fmt">
  function price(n) { return (n / 100).toFixed(2) } module.exports = { price:
  price }
</wxs>
<view>{{ fmt.price(1990) }}</view>
```

- 运行在**视图层**，与 JS 逻辑层**不是同一运行环境**。
- **不能调用 `wx.*` API，不能调用逻辑层定义的函数**。
- 适用于：数据格式化（价格、时间）、**WXS 响应事件**（视图层直接响应手势，不经过逻辑层，避免通信延迟 → 用于高性能交互动画）。

## 九、事件系统

### 9.1 绑定方式

```html
<!-- 冒泡：bind -->
<view bind:tap="onTap">点我</view>
<!-- 阻止冒泡：catch -->
<view catch:tap="onTap">点我</view>
<!-- 互斥：mut-bind（只触发一个） -->
<!-- 捕获阶段：capture-bind / capture-catch -->
```

### 9.2 `bind` vs `catch`

| 写法                     | 是否阻止冒泡       |
| ------------------------ | ------------------ |
| `bind:tap` / `bindtap`   | 否（继续向上冒泡） |
| `catch:tap` / `catchtap` | **是**             |

### 9.3 事件对象

```js
Page({
  onTap(e) {
    e.type; // 事件类型
    e.timeStamp; // 时间戳
    e.target; // 触发事件的源组件（可能是内部子元素）
    e.currentTarget; // 绑定事件的当前组件 ← 取 data-* 用这个
    e.detail; // 额外信息（如 input 的 value、form 的提交值）
    e.touches; // 触摸点数组
  },
});
```

```html
<view data-id="{{item.id}}" data-index="{{idx}}" bind:tap="onTap">点我</view>
```

```js
onTap(e) {
  const { id, index } = e.currentTarget.dataset // ← 正确
  // e.target.dataset 在点到子元素时会取不到！
}
```

> 🔥 **经典坑**：用 `e.target.dataset` 取不到数据。因为点击可能落在子元素上，`e.target` 是子元素。**取 `data-*` 一律用 `e.currentTarget.dataset`**。

### 9.4 注意事项

- `data-*` 中大写会自动转小写、连字符转驼峰（`data-user-id` → `dataset.userId`）。
- `bind:tap` 中 `tap` 是移动端"轻点"，不是 `click`。
- `scroll-view` 上的 `bindscroll` 高频触发，注意节流。

## 十、setData 与性能优化

### 10.1 原理

```js
this.setData({ key: value });
```

1. 逻辑层把数据 **JSON 序列化** 后经 Native 传给视图层。
2. 视图层反序列化并做**虚拟 DOM diff**。
3. 更新真实节点。

**结论：`setData` 是整个小程序最主要的性能瓶颈。**

### 10.2 硬限制与坑

| 限制                | 说明                                                                   |
| ------------------- | ---------------------------------------------------------------------- |
| 单次 `setData` 数据 | **不超过 1MB**（1024KB），超限报错                                     |
| `data` 中所有数据   | 页面卸载前不要超过合理大小（建议 < 256KB）                             |
| 频率                | 不要每秒多次高频调用（如 `onPageScroll`、`scroll` 事件里直接 setData） |

### 10.3 优化写法

```js
// ❌ 错误：一次性 setData 整个大列表
this.setData({ list: newBigList })

// ✅ 正确：只更新变化的某一项（路径写法）
this.setData({
  [`list[${index}].name`]: '新名字',
  'user.avatar': url
})

// ❌ 错误：渲染用不到的字段塞进 data
this.setData({ rawData: hugeObject })

// ✅ 正确：纯数据字段（不参与渲染）挂到 this 上
this.rawData = hugeObject

// 组件中用 pureDataPattern 声明纯数据字段
Component({
  options: { pureDataPattern: /^_/ },  // 以 _ 开头的字段不参与渲染
  data: { _internal: {...}, visible: true }
})

// 合并多次更新（避免一帧内多次 setData）
```

### 10.4 其他性能要点

- **长列表必须虚拟化**：超过几十条就用 `recycle-view` / 自己实现可视区渲染，或分页 + `onReachBottom`。
- **图片优化**：用 CDN、按需裁剪（七牛/腾讯云的图片处理参数）、懒加载 `<image lazy-load>`、指定 `mode` 避免布局抖动。
- **减少首屏 data 体积**：初始 `data` 越小，`onReady` 越快。
- **开启按需注入**：`app.json` 中 `"lazyCodeLoading": "requiredComponents"`。
- **初始渲染缓存**：`"initialRenderingCache": "static"` 可让非首次启动瞬间显示骨架。
- **避免 `onPageScroll` 中 `setData`**：如需吸顶效果，用 `position: sticky` 或 CSS 实现。
- **骨架屏**：首屏加载时展示骨架，减少白屏感。

## 十一、自定义组件

### 11.1 基本结构

```json
// components/my-card/my-card.json
{ "component": true, "usingComponents": {} }
```

```js
// components/my-card/my-card.js
Component({
  options: {
    styleIsolation: "isolated", // isolated | apply-shared | shared
    multipleSlots: true,
    pureDataPattern: /^_/,
  },
  properties: {
    title: { type: String, value: "" },
    count: {
      type: Number,
      value: 0,
      observer(n, o) {
        /* 变化监听 */
      },
    },
  },
  data: { inner: 1 },
  observers: {
    "title, count"(title, count) {
      /* 多字段监听 */
    },
  },
  methods: {
    onTap() {
      this.triggerEvent(
        "myevent",
        { value: 1 },
        { bubbles: true, composed: true },
      );
    },
  },
  lifetimes: { attached() {}, detached() {} },
  pageLifetimes: { show() {}, hide() {} },
});
```

### 11.2 通信方式

| 方向                | 方式                                               |
| ------------------- | -------------------------------------------------- |
| 父 → 子             | `properties`（属性传值）                           |
| 子 → 父             | `this.triggerEvent('eventName', detail, options)`  |
| 父 → 子（方法调用） | `this.selectComponent('#id')` 拿到实例直接调用方法 |
| 跨组件              | `relations` 定义组件间关系 / 全局状态 / EventBus   |
| 页面 → 组件         | `selectComponent` + 方法调用                       |

### 11.3 坑点

1. **`properties` 中不要直接修改传入的值**，应 `this.setData` 修改 `data`。
2. **`observer` 在初始化时也会触发**，注意区分。
3. `selectComponent` 在组件未渲染完成时返回 `null`，需要在 `onReady` 后调用或用 `wx.nextTick`。
4. **slot 默认只能有一个**，多插槽需 `options: { multipleSlots: true }` 并用 `name` 区分。
5. 组件样式默认隔离，想让页面样式影响组件需 `styleIsolation: 'apply-shared'`。
6. **页面也可以直接用 `Component` 构造**（`Component({...})` 注册页面），此时可使用 `properties`、`observers` 等能力，官方推荐复杂页面这么做。

## 十二、网络请求与服务器域名

### 12.1 服务器域名配置规则（高频踩坑）

后台 → 开发 → 开发设置 → 服务器域名。

| 规则                | 说明                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------- |
| 协议                | 只支持 `https`（request/uploadFile/downloadFile）和 `wss`（socket）                                       |
| 域名                | **不能用 IP 地址或 localhost**（局域网 IP 除外）                                                          |
| 备案                | **域名必须 ICP 备案**                                                                                     |
| 端口                | https 域名**可配置端口**，配置后只能访问该端口；**不配端口则请求 URL 中也不能带端口**（连 `:443` 都不行） |
| wss                 | 无需配置端口，默认允许所有端口                                                                            |
| 子域名              | **不支持配置父域名、使用子域名**，需逐个配置                                                              |
| `api.weixin.qq.com` | ❌ **不允许配置为服务器域名**，相关调用必须走服务端                                                       |
| 数量                | 每类域名可配置数量有限（通常 20 个左右），按月可改次数有限（通常 5 次/月）                                |

> 🔥 **经典坑**：配置 `https://api.example.com`，然后请求 `https://api.example.com:443` → 失败。因为配了不带端口的域名，URL 里就不能带端口。

### 12.2 使用限制

| 项                                           | 限制                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| `wx.request` 最大并发                        | **10** 个                                                                              |
| `wx.uploadFile` / `wx.downloadFile` 最大并发 | 10 个                                                                                  |
| `wx.connectSocket` 最大并发                  | **5** 个                                                                               |
| 默认超时                                     | 60s（`app.json` 的 `networkTimeout` 或 `wx.request({timeout})`，后者优先）             |
| 后台运行                                     | 进入后台后 **5s** 内请求未完成 → `fail interrupted`；回前台前无法再发起请求            |
| `referer`                                    | **不可设置**，格式固定为 `https://servicewechat.com/{appid}/{version}/page-frame.html` |
| 返回值编码                                   | 建议 UTF-8；框架会过滤一个 BOM 头                                                      |

### 12.3 `success` 的判定

> ⚠️ **坑**：**只要收到服务器响应，无论 `statusCode` 是多少（404/500），都进 `success` 回调。** 必须自己判断 `res.statusCode === 200`。

```js
wx.request({
  url: "https://api.example.com/list",
  method: "GET",
  data: { page: 1 },
  header: { "content-type": "application/json" },
  timeout: 10000,
  success(res) {
    if (res.statusCode !== 200) {
      /* 业务错误处理 */ return;
    }
    // 正常逻辑
  },
  fail(err) {
    /* 网络错误 / 超时 / 域名不合法 */
  },
});
```

### 12.4 HTTPS 证书要求

- 证书必须有效、被系统信任、域名匹配、在有效期内、**信任链完整**（缺中间证书是常见失败原因）。
- iOS **不支持自签名证书**，且需满足 ATS 要求。
- TLS 必须支持 1.2 及以上（同时建议兼容 1.2 以下以覆盖老 Android）。

### 12.5 跳过域名校验（仅开发）

开发者工具 → 详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。

> ⚠️ **坑**：真机上不勾选"调试模式"时校验生效。出现"开调试能请求，关调试不能请求"= 域名没配对。

### 12.6 推荐封装（统一登录态 + 错误处理）

```js
// utils/request.js
const BASE = "https://api.example.com";

function request(
  url,
  { method = "GET", data = {}, needAuth = true, loading = false } = {},
) {
  if (loading) wx.showLoading({ title: "加载中", mask: true });
  const token = wx.getStorageSync("token");
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE + url,
      method,
      data,
      header: {
        "content-type": "application/json",
        ...(needAuth && token ? { Authorization: "Bearer " + token } : {}),
      },
      timeout: 15000,
      success(res) {
        if (loading) wx.hideLoading();
        if (res.statusCode === 401) {
          // 登录态过期 → 重新登录
          return loginAndRetry(url, { method, data, needAuth }).then(
            resolve,
            reject,
          );
        }
        if (res.statusCode !== 200)
          return reject(new Error(`HTTP ${res.statusCode}`));
        const body = res.data;
        if (body.code === 0) resolve(body.data);
        else {
          wx.showToast({ title: body.msg || "请求失败", icon: "none" });
          reject(new Error(body.msg));
        }
      },
      fail(err) {
        if (loading) wx.hideLoading();
        wx.showToast({ title: "网络异常，请稍后重试", icon: "none" });
        reject(err);
      },
    });
  });
}
export default request;
```

## 十三、数据缓存与文件系统

### 13.1 Storage

```js
wx.setStorageSync("key", value); // 同步
wx.getStorageSync("key");
wx.removeStorageSync("key");
wx.clearStorageSync();
wx.setStorage({ key, data }); // 异步
wx.getStorageInfoSync(); // { keys, currentSize, limitSize }
```

| 限制             | 值                                                   |
| ---------------- | ---------------------------------------------------- |
| 单个 key 最大    | 1MB                                                  |
| 单个小程序总上限 | **10MB**                                             |
| 生命周期         | 与小程序一致，**用户删小程序才清除**；不跨小程序共享 |

> ⚠️ **坑**：
>
> 1. `getStorageSync('notExist')` 返回 `''`（空字符串）而不是 `null`/`undefined`，判空要注意。
> 2. 存储的是**副本**，对象取出后修改不会自动写回。
> 3. 用户切换微信账号 / 换设备 → 缓存丢失，不要用它存核心业务数据。
> 4. 微信有自动清理策略（LRU），超限时可能被清理。

### 13.2 文件系统

```js
const fs = wx.getFileSystemManager();
fs.writeFileSync(`${wx.env.USER_DATA_PATH}/a.txt`, "hello", "utf8");
fs.readFileSync(`${wx.env.USER_DATA_PATH}/a.txt`, "utf8");
```

- `wx.env.USER_DATA_PATH` 是可读写目录（相当于 App 沙盒）。
- **本地文件总上限 200MB**（部分场景 10MB，如 `wx.saveFile` 保存的文件）。
- 临时文件（`wx.chooseImage` / `wx.downloadFile` 产生的）会被系统清理，重要文件要 `fs.saveFile` 转持久。

## 十四、分包加载

### 14.1 为什么必须分包

| 限制           | 值                                                                               |
| -------------- | -------------------------------------------------------------------------------- |
| 主包大小       | **≤ 2MB**                                                                        |
| 单个分包大小   | **≤ 2MB**                                                                        |
| 全部分包总大小 | 上限（官方曾多次调整，目前为 30MB；低版本客户端为 20MB）— 以官方文档最新说明为准 |

> 超过就必须分包，否则无法上传。

### 14.2 配置

```json
{
  "pages": ["pages/index/index", "pages/mine/mine"],
  "subPackages": [
    {
      "root": "packageA",
      "name": "packA",
      "pages": ["pages/cat", "pages/dog"],
      "entry": "index.js"
    },
    {
      "root": "packageB",
      "pages": ["pages/apple", "pages/banana"],
      "independent": false
    }
  ],
  "preloadRule": {
    "pages/index/index": {
      "network": "all",
      "packages": ["packA"]
    }
  }
}
```

> 写成 `subpackages`（全小写）也可以。

### 14.3 分包原则（必记）

1. **`tabBar` 页面必须在主包内**。
2. **分包根目录不能嵌套**（分包里不能再有分包）。
3. **未在 `subPackages` 中声明的目录，会被全部打进主包**（主包悄悄膨胀的头号原因）。
4. **分包之间不能互相引用**：
   - `packageA` 不能 `require` `packageB` 的 JS；
   - 不能 `import` `packageB` 的 template；
   - 不能使用 `packageB` 的资源（图片等）。
   - 但**都可以引用主包**，也可以引用自己包内。
   - 需要跨分包引用 → 使用「分包异步化」。
5. 分包可以引用主包的公共组件/工具（这也是主包变大的原因，要克制）。

### 14.4 独立分包（`independent: true`）

- 独立分包**不依赖主包**即可运行，可独立启动（用于"直达某个页"的场景，如分享落地页）。
- ⚠️ 坑：独立分包中**不能引用主包的资源**（App 实例也不在主包中），共享逻辑必须重复打包或在分包内自包含。
- ⚠️ 坑：独立分包中 `getApp()` 返回 `undefined`（主包未加载），需要 `getApp({ allowDefault: true })`。

### 14.5 分包预下载

```json
"preloadRule": {
  "pages/index/index": { "network": "all", "packages": ["packA"] },
  "pages/mine/mine":   { "network": "wifi", "packages": ["__APP__"] }
}
```

- `__APP__` 表示主包。
- `network`：`all` / `wifi`。
- 用 `name` 或 `root` 引用分包，`name` 需先定义。

### 14.6 分包体积优化实操

1. 图片/字体/视频**全部放 CDN**，代码包里不放大文件。
2. 开启「上传时压缩」（开发者工具 / CI）。
3. 用**代码依赖分析**（开发者工具 → 代码质量分析）找出意外进主包的模块。
4. 公共组件按需放主包，冷门页面放分包。
5. 不用的第三方库删掉，或用 ESM 按需引入。

## 十六、登录体系：code / openid / unionid / session_key

> 这是小程序开发**最容易搞错**的一块，务必理解清楚。

### 16.1 四个概念辨析

| 概念            | 是什么                            | 谁生成                   | 有效期                  | 用途                                                   |
| --------------- | --------------------------------- | ------------------------ | ----------------------- | ------------------------------------------------------ |
| **code**        | 临时登录凭证                      | 微信客户端（`wx.login`） | **5 分钟**              | 换取 `openid` + `session_key`；**一次性**              |
| **openid**      | 用户在本小程序下的唯一 ID         | 微信服务端               | 永久（对该 appid）      | 标识用户身份                                           |
| **unionid**     | 用户在同一开放平台账号下的唯一 ID | 微信服务端               | 永久                    | 打通同一主体的多个应用                                 |
| **session_key** | 会话密钥                          | 微信服务端               | 会过期（用户行为/时间） | **解密** encryptedData（如手机号、微信运动）；校验签名 |

再补两个易混：

| 概念                      | 是什么                                                  | 有效期                            |
| ------------------------- | ------------------------------------------------------- | --------------------------------- |
| **access_token**          | 小程序全局唯一后台接口调用凭据（服务端用 AppSecret 换） | **7200 秒**，需缓存，日调用有上限 |
| **自定义登录态（token）** | **你自己服务端签发**的登录态                            | 自己定                            |

### 16.2 关键差异：openid vs unionid

```text
同一开放平台账号
├── 小程序 A  →  用户 U 的 openid = oA_xxx   ┐
├── 小程序 B  →  用户 U 的 openid = oB_yyy   ├── 三者 unionid 相同 = oU_zzz
└── 公众号 C  →  用户 U 的 openid = oC_www   ┘

不同开放平台账号 → 同一用户 unionid 不同
```

- **openid**：换 appid 就变，只在单个应用内唯一。
- **unionid**：同一开放平台账号下唯一，用于跨应用打通用户体系。
- ⚠️ **坑**：把 openid 当 unionid 用于打通多端，是数据串号事故的常见原因。

### 16.3 标准登录时序图（官方推荐）

```text
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│   小程序端    │        │  开发者服务端  │        │   微信服务器   │
└──────┬───────┘        └──────┬───────┘        └──────┬───────┘
       │  ①wx.login()          │                       │
       │───────────────────────│                       │
       │  返回 code（5分钟有效） │                       │
       │                       │                       │
       │  ②wx.request({code})  │                       │
       │──────────────────────►│                       │
       │                       │  ③code2Session        │
       │                       │  (appid+secret+code)  │
       │                       │──────────────────────►│
       │                       │  {openid, session_key,│
       │                       │   unionid?}           │
       │                       │◄──────────────────────│
       │                       │                       │
       │                       │ ④生成自定义登录态 token │
       │                       │   关联 openid 存库     │
       │  ⑤返回 token          │                       │
       │◄──────────────────────│                       │
       │                       │                       │
       │  ⑥wx.setStorageSync   │                       │
       │     ('token', token)  │                       │
       │                       │                       │
       │  ⑦后续请求带 token     │                       │
       │──────────────────────►│ ⑧校验 token → openid  │
```

### 16.4 前端代码

```js
// utils/auth.js
let loginPromise = null;

function login() {
  if (loginPromise) return loginPromise; // 并发去重，避免重复 wx.login
  loginPromise = new Promise((resolve, reject) => {
    wx.login({
      timeout: 10000,
      success(res) {
        if (!res.code) return reject(new Error("wx.login 失败：" + res.errMsg));
        request("/api/auth/login", {
          method: "POST",
          data: { code: res.code },
          needAuth: false,
        })
          .then((data) => {
            wx.setStorageSync("token", data.token);
            wx.setStorageSync("openid", data.openid);
            resolve(data);
          })
          .catch(reject)
          .finally(() => {
            loginPromise = null;
          });
      },
      fail: reject,
    });
  });
  return loginPromise;
}

// 启动时检查登录态
async function ensureLogin() {
  const token = wx.getStorageSync("token");
  if (token) {
    try {
      const ok = await wx.checkSession(); // 只检查 session_key 是否过期（微信侧）
      if (ok) return token;
    } catch (e) {
      /* session_key 已过期，需重新 login */
    }
  }
  await login();
  return wx.getStorageSync("token");
}
```

### 16.5 服务端 `code2Session`

```text
GET https://api.weixin.qq.com/sns/jscode2session
  ?appid=APPID
  &secret=APPSECRET
  &js_code=JSCODE
  &grant_type=authorization_code
```

**成功返回：**

```json
{
  "openid": "oUpF8uMuAJO_M2pxb1Q9zNjWeS6o",
  "session_key": "tiiihtGNzX9FpaHMUfKgtA==",
  "unionid": "o6_bmasdasdsad6_2sgVt7hMZOPfL" // 满足条件才返回
}
```

**失败返回：**

```json
{ "errcode": 40029, "errmsg": "invalid code" }
```

| errcode | 含义                                    |
| ------- | --------------------------------------- |
| 40029   | code 无效（已用过 / 过期 / 非本小程序） |
| 45011   | API 调用太频繁（频率限制）              |
| 40226   | code 被封禁（高风险用户）               |

### 16.6 `session_key` 的用途与安全

用途：

1. **解密敏感数据**：`encryptedData` + `iv` + `session_key` → AES-128-CBC 解密（旧版 `getUserInfo`、手机号旧方案、`getWeRunData` 等）。
2. **校验签名**：`signature = sha1(rawData + session_key)`。

> 🔥 **核心安全红线（官方原文）**：
>
> 1. **`session_key` 绝不下发到小程序，也不对外提供**。它只应存在于服务端。
> 2. **`code` 只能使用一次**。

其他注意：

- `session_key` 会因用户重新登录、长时间未使用等原因失效 → 用 `wx.checkSession()` 检测，失效则重新 `wx.login`。
- **不要用 `session_key` 当自己的登录态**，它是微信的密钥，不是你的会话。

### 16.7 UnionID 获取的三种途径

| 途径                                 | 是否需要用户授权 | 说明                                                  |
| ------------------------------------ | ---------------- | ----------------------------------------------------- |
| ① `wx.login` → 服务端 `code2Session` | **否**           | ✅ **推荐主路径**，静默获取                           |
| ② 云函数中 `Cloud.getWXContext()`    | 否               | 仅云开发场景                                          |
| ③ 支付后 `getPaidUnionID`            | 否               | 需先完成支付，**仅支付后 5 分钟内有效**；不支持小游戏 |

**前提条件：小程序必须已绑定到微信开放平台账号**，否则 `code2Session` 不返回 `unionid`。

**绑定路径**（官方强调容易走错）：

```text
登录 https://developers.weixin.qq.com/platform
  → 控制台首页
  → 我的业务 → 开放平台 → 绑定关系 → 小程序
```

> ⚠️ **不是**「我的业务 → 小程序 → 绑定关系 → 开放平台」，方向相反，走错就配不上。

**其他注意**：

- 开放平台账号需**认证**（300元/年）后才能绑定小程序。
- 同一小程序**只能绑定到一个开放平台账号**。
- 新用户首次访问时 `unionid` 可能尚未生成，需确保用户与小程序产生过交互。

### 16.8 完整登录最佳实践清单

| #   | 原则                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------- |
| 1   | **永远不要**在小程序端调用任何需要 AppSecret 的接口                                                           |
| 2   | 前端只传 `code`，服务端换 `openid/session_key`，返回**自己签发的 token**                                      |
| 3   | `session_key` 只存服务端（Redis + 过期时间），不下发                                                          |
| 4   | `code` 一次性，服务端换取后立即丢弃                                                                           |
| 5   | 用 `wx.checkSession` 判断是否需要重新 `wx.login`（注意它只判断微信侧 session_key，**你的 token 过期要另判**） |
| 6   | 登录请求做**并发去重**（多个页面同时触发只发一次）                                                            |
| 7   | 服务端对 `code2Session` 做**频率限制与失败重试**，处理 45011                                                  |
| 8   | 需要跨端打通时存 `unionid`，并给"拿不到 unionid"留降级方案                                                    |
| 9   | 敏感操作（支付、改绑手机号）务必在服务端二次校验用户身份                                                      |

## 十七、授权体系：scope / authorize / getSetting / openSetting

### 17.1 授权弹窗的三条规则（必记）

| 用户历史操作           | 系统行为                         |
| ---------------------- | -------------------------------- |
| **未接受、也未拒绝过** | 弹窗询问，同意后可调用           |
| **已授权**             | 直接调用，无弹窗                 |
| **已拒绝过**           | **不再弹窗**，直接进 `fail` 回调 |

> 🔥 **最重要的坑**：用户一旦拒绝过，`wx.authorize` **永远不会再弹窗**。此时**必须**引导用户去设置页，不能死等弹窗。
> 官方明确要求：**请开发者兼容用户拒绝授权的场景。**

### 17.2 三个核心 API

| API              | 作用                         |
| ---------------- | ---------------------------- |
| `wx.getSetting`  | 查询当前授权状态             |
| `wx.authorize`   | **提前**发起授权请求（弹窗） |
| `wx.openSetting` | 打开设置页，让用户手动开启   |

**设置页入口（用户侧）**：小程序右上角 → 关于 → 右上角 → 设置。

### 17.3 标准授权流程

```js
// 通用授权封装：查询 → 申请 → 失败引导设置页
function ensureAuth(scope, tip) {
  return new Promise((resolve, reject) => {
    wx.getSetting({
      success(res) {
        const setting = res.authSetting;
        if (setting[scope] === true) return resolve(true); // 已授权
        if (setting[scope] === false) {
          // 已拒绝 → 只能去设置页
          wx.showModal({
            title: "需要授权",
            content: tip || "请在设置中开启相应权限",
            confirmText: "去设置",
            success(r) {
              if (r.confirm) {
                wx.openSetting({
                  success(s) {
                    s.authSetting[scope]
                      ? resolve(true)
                      : reject(new Error("user denied"));
                  },
                });
              } else reject(new Error("user cancel"));
            },
          });
          return;
        }
        // 从未表态 → 弹窗申请
        wx.authorize({
          scope,
          success: () => resolve(true),
          fail: () => reject(new Error("authorize fail")),
        });
      },
      fail: reject,
    });
  });
}

// 使用
await ensureAuth("scope.writePhotosAlbum", "保存图片需要相册权限");
wx.saveImageToPhotosAlbum({ filePath });
```

即：授权状态是**持久化**的，不因会话结束而重置。想重置只能删除小程序或重装微信。

### 17.6 头像昵称的重要变更（必知）

```js
Page({
```

### 17.7 授权注意事项

1. **按需授权**：在真正要用时才申请，并在申请中说明用途。
2. **地理位置**：必须在 `app.json` 的 `permission` 字段配置用途说明，否则**授权弹窗不会出现**。
3. **隐私保护指引**：授权弹窗会展示你在《小程序用户隐私保护指引》中填写的说明，**谨慎填写**。
4. **后台定位**：
   - 先在 `app.json` 的 `requiredBackgroundModes` 声明 `"location"`。
   - Android 8.0.0 / iOS 8.0.0 起可用 `wx.authorize({scope:'scope.userLocationBackground'})` 唤起授权。
   - 更低版本**不会弹窗**，需引导用户到设置页手动开启。
5. **`wx.authorize` 只弹一次**（未表态时），重复调用不会重复弹窗。
6. `wx.openSetting` 自基础库 2.x 起只能通过**用户点击行为**（button / modal）触发，不能自动调用。

| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 十九、微信支付全流程

> 小程序支付 = **JSAPI 支付**。核心是：服务端下单拿 `prepay_id` → 服务端签名 → 前端 `wx.requestPayment` 调起 → 服务端接收回调确认。

### 19.1 整体时序图


### 19.2 接入前置条件

| #   | 事项                                                                                     |
| --- | ---------------------------------------------------------------------------------------- |
| 1   | 小程序主体必须是**企业/个体工商户**（个人主体无法开通支付）                              |
| 2   | 小程序完成**微信认证**                                                                   |
| 3   | 申请**微信支付商户号**（商户平台 pay.weixin.qq.com），需营业执照、法人身份证、对公账户等 |
| 4   | 在商户平台完成**AppID 与商户号绑定**（小程序后台 → 微信支付 → 关联商户号，商户平台确认） |
| 5   | 设置 **API 密钥（v2）**、下载 **API 证书（v3）**、获取**商户 API 证书序列号**            |
| 6   | 配置 **APIv3 密钥**（用于回调解密）、**微信支付公钥 / 平台证书**（用于验签）             |
| 7   | 配置 **支付回调地址 notify_url**（外网可访问、HTTPS、不能有 `?` 参数）                   |
| 8   | 服务类目与小程序类目匹配（虚拟支付有特殊规则）                                           |

### 19.3 服务端：JSAPI / 小程序下单（APIv3）

```text
POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi
Header:
  Authorization: WECHATPAY2-SHA256-RSA2048 mchid="...",nonce_str="...",signature="...",timestamp="...",serial_no="..."
  Accept: application/json
  Content-Type: application/json
  Wechatpay-Serial: {微信支付公钥ID}
```

**请求体（必填字段）：**

```json
{
  "appid": "wxd678efh567hg6787",
  "mchid": "1230000109",
  "description": "Image形象店-深圳腾大-QQ公仔",
  "out_trade_no": "1217752501201407033233368018",
  "notify_url": "https://www.weixin.qq.com/wxpay/pay/callback",
  "amount": {
    "total": 100,
    "currency": "CNY"
  },
  "payer": {
    "openid": "oUpF8uMuAJO_M2pxb1Q9zNjWeS6o"
  }
}
```

**可选字段：**

| 字段                         | 说明                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `time_expire`                | 支付结束时间，rfc3339 格式 `2018-06-08T10:34:56+08:00`；不能早于下单后 1 分钟，不超过 15 天；不传则默认 7 天 |
| `attach`                     | 商户数据包（≤128字符），回调原样返回，会体现在账单                                                           |
| `goods_tag`                  | 订单优惠标记（配合代金券）                                                                                   |
| `support_fapiao`             | 电子发票入口标识，需先开通电子发票功能                                                                       |
| `detail`                     | 商品详情（`cost_price`、`invoice_id`、`goods_detail[]`），压缩后 ≤6144 字节                                  |
| `scene_info`                 | 场景信息（`payer_client_ip`、`device_id`、`store_info`）                                                     |
| `settle_info.profit_sharing` | 分账标识，`true` 时资金冻结至分账完成，或支付成功 30 天后自动解冻                                            |

**响应：**

```json
{ "prepay_id": "wx201410272009395522657a690389285100" }
```

> ⚠️ **`prepay_id` 有效期 2 小时**，失效需重新下单。

**常见错误码：**

| 状态码 | 错误码                  | 含义                 |
| ------ | ----------------------- | -------------------- |
| 400    | `APPID_MCHID_NOT_MATCH` | AppID 与商户号未绑定 |
| 400    | `MCH_NOT_EXISTS`        | 商户号不存在         |
| 401    | `SIGN_ERROR`            | 签名错误             |
| 403    | `NO_AUTH`               | 商户无该接口权限     |
| 403    | `OUT_TRADE_NO_USED`     | **商户订单号重复**   |
| 429    | `FREQUENCY_LIMITED`     | 请求频率超限         |

### 19.4 服务端：生成调起支付签名（APIv3）

**签名串（4 行，末尾必须加换行）：**

```text
appId
timeStamp
nonceStr
package
```

即：`appId + "\n" + timeStamp + "\n" + nonceStr + "\n" + package + "\n"`

其中 `package` = `"prepay_id=" + prepay_id`

**签名算法**：`RSA-SHA256`（用**商户 API 证书私钥**），结果 Base64 → `paySign`

```js
// Node.js 示例
const crypto = require("crypto");
const fs = require("fs");

function buildPayParams(appId, prepayId) {
  const timeStamp = Math.floor(Date.now() / 1000).toString();
  const nonceStr = crypto.randomBytes(16).toString("hex").slice(0, 32);
  const pkg = `prepay_id=${prepayId}`;

  const message = `${appId}\n${timeStamp}\n${nonceStr}\n${pkg}\n`;
  const privateKey = fs.readFileSync("/path/to/apiclient_key.pem", "utf8");

  const sign = crypto.createSign("RSA-SHA256");
  sign.update(message);
  const paySign = sign.sign(privateKey, "base64");

  return {
    timeStamp, // 注意：字符串
    nonceStr,
    package: pkg, // 注意：是 package 不是 prepay_id
    signType: "RSA",
    paySign,
  };
}
```

> 🔥 **签名三大坑**：
>
> 1. **字段名是 `package` 不是 `prepayId`/`prepay_id`**，且值是 `"prepay_id=xxx"` 带前缀。
> 2. **签名串末尾必须有 `\n`**（第 4 行后也要换行）。
> 3. **`timeStamp` 必须是字符串**（秒级）。传数字会导致签名失败。
> 4. **v2 用 MD5/HMAC-SHA256，v3 用 RSA-SHA256**，`signType` 要对应，不要混用。
> 5. 参与签名的 `appId` 是驼峰（`I` 大写），不是 `appid`。

### 19.5 前端：调起支付

```js
Page({
  async pay(orderId) {
    try {
      wx.showLoading({ title: "正在发起支付", mask: true });
      // ① 请求自己的服务端下单
      const payParams = await request("/api/pay/create", {
        method: "POST",
        data: { orderId },
      });
      wx.hideLoading();

      // ② 调起微信支付
      await new Promise((resolve, reject) => {
        wx.requestPayment({
          timeStamp: payParams.timeStamp,
          nonceStr: payParams.nonceStr,
          package: payParams.package,
          signType: payParams.signType, // 'RSA'（v3）或 'MD5'（v2）
          paySign: payParams.paySign,
          success: resolve,
          fail: reject,
        });
      });

      // ③ 前端 success 只代表"用户完成支付动作"，不代表订单已确认！
      //    必须查服务端订单状态
      wx.showLoading({ title: "确认支付结果", mask: true });
      const result = await this.queryOrderStatus(orderId); // 轮询或等回调
      wx.hideLoading();
      if (result.paid) {
        wx.showToast({ title: "支付成功" });
        wx.redirectTo({ url: "/pages/order/result?orderId=" + orderId });
      } else {
        wx.showToast({ title: "支付结果确认中，请稍后查看订单", icon: "none" });
      }
    } catch (err) {
      wx.hideLoading();
      // requestPayment:fail cancel 是用户主动取消，不要当错误处理
      if (String(err.errMsg).includes("cancel")) {
        wx.showToast({ title: "已取消支付", icon: "none" });
      } else {
        wx.showToast({
          title: "支付失败：" + (err.errMsg || "未知错误"),
          icon: "none",
        });
      }
    }
  },

  // 轮询查单（兜底，防止回调丢失）
  async queryOrderStatus(orderId, maxRetry = 5) {
    for (let i = 0; i < maxRetry; i++) {
      const r = await request("/api/pay/status", { data: { orderId } });
      if (r.paid) return { paid: true };
      await new Promise((res) => setTimeout(res, 1000));
    }
    return { paid: false };
  },
});
```

### 19.6 服务端：支付回调处理（最关键）

```js
// 伪代码：Express 回调接口
app.post("/api/wxpay/notify", async (req, res) => {
  // ① 必须拿到原始 body（不能经过 body-parser 的 json 解析覆盖）
  const timestamp = req.headers["wechatpay-timestamp"];
  const nonce = req.headers["wechatpay-nonce"];
  const signature = req.headers["wechatpay-signature"];
  const serial = req.headers["wechatpay-serial"];
  const body = req.rawBody; // 原始字符串

  // ② 验签（用微信支付公钥/平台证书）
  const ok = verifySignature({ timestamp, nonce, body, signature, serial });
  if (!ok) return res.status(401).send(buildFail("签名验证失败"));

  // ③ 解密 resource（AES-256-GCM，密钥 = APIv3 密钥）
  const resource = JSON.parse(body).resource;
  const plain = decryptResource(resource, API_V3_KEY);
  const data = JSON.parse(plain);

  // ④ 幂等：用 out_trade_no + transaction_id 判重（防止重复发货）
  const exists = await Order.isNotified(data.out_trade_no);
  if (exists) return res.status(200).send(buildSuccess()); // 已处理，直接成功应答

  // ⑤ 校验金额（防止篡改）
  const order = await Order.findByNo(data.out_trade_no);
  if (!order || order.amountFen !== data.amount.total) {
    return res.status(200).send(buildFail("订单金额不符")); // 注意仍返回 200
  }

  // ⑥ 业务处理（同一事务内）
  await db.transaction(async (t) => {
    await Order.markPaid(data.out_trade_no, data.transaction_id, t);
    await Delivery.create(data.out_trade_no, t);
    await Coupon.consume(data.out_trade_no, t);
  });

  // ⑦ 必须应答 SUCCESS，否则微信会按 15s/15s/30s/3m/10m/20m/30m/30m/30m/60m/3h/3h/3h/6h/6h/6h 共 15 次重发
  res.status(200).send(buildSuccess());
});

function buildSuccess() {
  return JSON.stringify({ code: "SUCCESS", message: "成功" });
}
function buildFail(msg) {
  return JSON.stringify({ code: "FAIL", message: msg });
}
```

### 19.7 支付回调铁律

| #   | 铁律                                                      | 原因                                              |
| --- | --------------------------------------------------------- | ------------------------------------------------- |
| 1   | **以服务端回调为准，不以前端 `success` 为准**             | 前端回调可能丢失（用户杀进程、网络断）            |
| 2   | **必须验签**                                              | 回调 URL 是公开的，不验签会被伪造"支付成功"       |
| 3   | **必须幂等**                                              | 微信会重复通知（未收到 SUCCESS 应答时最多 15 次） |
| 4   | **必须校验金额**                                          | 防止订单金额被篡改                                |
| 5   | **5 秒内返回**，且 HTTP 状态码 200 + `{"code":"SUCCESS"}` | 超时会触发重试；返回非 200 也视为失败             |
| 6   | **业务逻辑异步化**                                        | 回调里做耗时操作（发货、发券）→ 先落库再异步处理  |
| 7   | `notify_url` 不能有查询参数                               | 微信不认                                          |
| 8   | 回调解密用 **APIv3 密钥**（32 位），不是 API 密钥（v2）   | 两者不同                                          |

### 19.8 其他支付接口

| 接口                                                                 | 用途                                     |
| -------------------------------------------------------------------- | ---------------------------------------- |
| `GET /v3/pay/transactions/out-trade-no/{out_trade_no}?mchid={mchid}` | 商户订单号查单（**兜底主动查单用这个**） |
| `GET /v3/pay/transactions/id/{transaction_id}?mchid={mchid}`         | 微信订单号查单                           |
| `POST /v3/pay/transactions/out-trade-no/{out_trade_no}/close`        | 关闭订单                                 |
| `POST /v3/refund/domestic/refunds`                                   | 申请退款                                 |
| `GET /v3/refund/domestic/refunds/{out_refund_no}`                    | 查询退款                                 |
| `POST /v3/pay/partner/transactions/jsapi`                            | 服务商模式                               |

### 19.9 支付常见坑汇总

| 现象                              | 原因                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| `requestPayment:fail` 无更多信息  | 通常是 `prepay_id` 过期（>2h）或签名错误                                                        |
| 提示"支付签名验证失败"            | 签名串末尾缺 `\n`；`timeStamp` 传了数字；字段名写成 `appid`；`package` 值没带 `prepay_id=` 前缀 |
| `APPID_MCHID_NOT_MATCH`           | AppID 与商户号未绑定（两边都要确认）                                                            |
| `INVALID_REQUEST` / `PARAM_ERROR` | `out_trade_no` 重复（403 `OUT_TRADE_NO_USED`）；金额单位错（必须是**分**）                      |
| 前端 success 但订单未支付         | 只信回调/查单，前端 success 不可信                                                              |
| 回调收不到                        | `notify_url` 非 HTTPS / 带参数 / 防火墙拦截 / 响应超时                                          |
| 重复发货                          | 回调未做幂等                                                                                    |
| 虚拟支付被拒审                    | iOS 端虚拟商品必须用**虚拟支付**（`wx.requestVirtualPayment`），不能用普通支付；否则审核被拒    |
| 退款失败                          | 余额不足 / 订单未支付 / 超过退款期限（1 年内）                                                  |

### 19.10 分账与其他

- `settle_info.profit_sharing: true` → 资金冻结，需主动分账 + 解冻剩余资金，或支付成功 **30 天后自动解冻**。
- 退款：`out_refund_no` 商户退款单号需唯一，退款金额 ≤ 订单金额。
- **iOS 虚拟支付**：iOS 端购买虚拟商品（会员、金币、课程等）必须使用 `wx.requestVirtualPayment`，走苹果内购通道，否则审核不通过且可能被下架。

## 二十、订阅消息

### 20.1 三种类型

| 类型               | 说明                                               | 开放范围                                         |
| ------------------ | -------------------------------------------------- | ------------------------------------------------ |
| **一次性订阅消息** | 用户订阅一次，开发者可下发**一条**；可多次订阅累积 | 所有小程序                                       |
| **长期订阅消息**   | 用户订阅一次，可长期多次下发                       | 仅政务民生、医疗、交通、金融、教育等**特定类目** |
| **设备订阅消息**   | 硬件设备场景                                       | 需硬件接入                                       |

### 20.2 使用

```js
wx.requestSubscribeMessage({
  tmplIds: ["TEMPLATE_ID_1", "TEMPLATE_ID_2", "TEMPLATE_ID_3"], // 最多 3 条
  success(res) {
    // res[TEMPLATE_ID] === 'accept' | 'reject' | 'ban' | 'filter' | 'acceptWithAudio'
    if (res["TEMPLATE_ID_1"] === "accept") {
      // 通知服务端记录订阅次数
    }
  },
  fail(err) {
    console.log(err.errCode); // 20004 用户关闭了主开关 / 43101 无订阅权限
  },
});
```

**服务端下发：**

```text
POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=ACCESS_TOKEN
{
  "touser": "OPENID",
  "template_id": "TEMPLATE_ID",
  "page": "pages/index/index",
  "miniprogram_state": "formal",
  "lang": "zh_CN",
  "data": {
    "thing1": { "value": "商品名称" },
    "amount2": { "value": "99.00" },
    "time3": { "value": "2026-10-10 10:00" }
  }
}
```

### 20.3 注意事项（坑）

1. **一次最多订阅 3 条模板**；一次订阅只能下发一条，"订阅 3 次可发 3 条"。
2. 必须由**用户点击行为**触发（button / 用户手势），不能页面加载就调。
3. `res[tmplId]` 取值：`accept`（同意）、`reject`（拒绝）、`ban`（后台封禁）、`filter`（模板被过滤）、`acceptWithAudio`（同意并开启语音提醒）。
4. 用户勾选「**总是保持以上选择**」后，后续调用**不再弹窗**，直接返回上次的授权结果 → 需配合 `wx.getSetting` 的 `subscriptionsSetting` 判断，并引导用户去设置页。
5. **模板字段有严格格式限制**：`thing` ≤ 20 字符、`character_string` 限数字字母、`amount` 需为数字且带单位、`time` 需 `yyyy-MM-dd HH:mm:ss`。格式不合规会报错 `47003`。
6. 模板需先在**公众平台选用**，拿到 `template_id` 和关键词。
7. `access_token` 要服务端缓存（7200s），不要每次请求都刷新。

| 代码包体积   | 分包；图片/字体/视频放 CDN；删除无用依赖；开启上传压缩             |
| 代码注入     | `"lazyCodeLoading": "requiredComponents"`（按需注入）              |
| 首屏渲染     | 骨架屏；首屏 data 最小化；避免首屏大量 `wx.request` 串行           |
| 请求优化     | 并行请求；数据预拉取（`wx.setBackgroundFetchToken`）；缓存首屏数据 |
| DNS          | 后台配置 DNS 预解析域名（最多 5 个）                               |
| 初始渲染缓存 | `"initialRenderingCache": "static"`                                |

### 21.2 运行时性能

| 优化项    | 做法                                                                                     |
| --------- | ---------------------------------------------------------------------------------------- |
| `setData` | 只传变化数据；路径更新；合批；不在 `onPageScroll` 中调用                                 |
| 长列表    | 虚拟列表 / 分页；必须带 `wx:key`                                                         |
| 图片      | CDN + 裁剪参数；`lazy-load`；指定 `mode` 与尺寸避免抖动；WebP                            |
| 动画      | 优先 CSS 动画 / `wx.createAnimation`；高性能用 WXS 响应事件或 Skyline Worklet            |
| 内存      | `detached` 清理定时器与监听；大对象放 `this` 不放 `data`；及时 `destroy` 音视频/相机实例 |
| 定时器    | 页面 `onUnload` 必须 `clearInterval` / `clearTimeout`                                    |

### 21.3 体验评分

开发者工具 → 调试器 → **Audits（体验评分）**，会给出性能、体验、最佳实践三方面的评分与建议。发布前建议跑一次。

## 二十二、安全指引

### 22.1 前端安全

| #   | 原则                                                                                                |
| --- | --------------------------------------------------------------------------------------------------- |
| 1   | **绝不**在小程序代码中硬编码 AppSecret、商户私钥、APIv3 密钥、数据库密码                            |
| 2   | 所有需要鉴权的接口在**服务端校验登录态**，不信任前端传的 openid（前端可伪造）                       |
| 3   | 用户输入必须校验长度与类型，防止 XSS（WXML 中 `{{}}` 会转义，但 `rich-text` 的 `nodes` 需自行过滤） |
| 4   | 不要把敏感信息（身份证、手机号明文）存 Storage                                                      |
| 5   | 代码上传前用开发者工具的「代码安全扫描」                                                            |
| 6   | 不要在 `data` 里放整个用户对象（含敏感字段）                                                        |

### 22.2 服务端安全（官方明确列出）

| 风险            | 防范                                                      |
| --------------- | --------------------------------------------------------- |
| **接口鉴权**    | 所有接口校验 token；水平越权校验（A 用户不能查 B 的订单） |
| **注入漏洞**    | SQL 用参数化查询；禁止拼接 shell 命令                     |
| **弱口令**      | 后台管理强密码 + 二次验证                                 |
| **文件上传**    | 校验类型/大小，重命名存储，不按原路径存放                 |
| **文件下载**    | 校验权限，防目录遍历                                      |
| **目录遍历**    | 路径参数做白名单校验                                      |
| **条件竞争**    | 支付回调、库存扣减用事务 + 乐观锁                         |
| **`code` 重放** | 一次性消费，服务端做去重                                  |

### 22.3 业务安全

- 支付回调必须验签 + 幂等 + 金额校验（见 [19.7](#197-支付回调铁律)）。
- 优惠券/库存扣减防并发超卖。
- 敏感操作（改绑手机、提现）加二次验证。

## 二十三、从开发到上线完整流程

### 23.1 四种版本概念

| 版本           | 说明                       | 数量                                               |
| -------------- | -------------------------- | -------------------------------------------------- |
| **开发版本**   | 开发者工具上传的代码       | **每人只保留最新一份**；可删除，不影响线上与审核中 |
| **体验版本**   | 从某个开发版本中选定的一份 | **只能有一份**                                     |
| **审核中版本** | 已提交审核等待结果         | **只能有一份**；有结果后可发布，也可重新提交覆盖   |
| **线上版本**   | 所有用户实际使用的版本     | 新版本发布后被覆盖                                 |

> ⚠️ **坑**：开发版每人只保留最新一份，A 上传会覆盖 A 之前的代码。多人协作时建议**指定专人上传稳定代码作为体验版**，避免测试/产品拿到不稳定的版本。

### 23.2 发布四步

```text
① 预览      开发者工具「预览」→ 扫码在真机验证（开发版，仅开发者本人可扫）
     ↓
② 上传代码  开发者工具「上传」→ 填版本号 + 项目备注
             （版本号建议语义化：1.0.0；备注写清变更点，便于回滚定位）
     ↓
③ 提交审核  mp.weixin.qq.com → 管理 → 版本管理 → 开发版本 → 提交审核
             填写测试账号、功能页面路径、补充说明、类目资质
     ↓
④ 发布      审核通过后，管理员微信收到通知 → 版本管理 → 审核版本 → 发布
             选「全量发布」或「分阶段发布（灰度）」
```

### 23.3 成员与权限

| 角色           | 关键权限                                                 |
| -------------- | -------------------------------------------------------- |
| **运营者**     | 提交审核、发布、回退、开发设置、微信支付、推广、暂停服务 |
| **开发者**     | 开发者工具、开发版                                       |
| **数据分析者** | 数据分析模块                                             |
| **体验成员**   | 仅使用体验版（由管理员或项目成员添加）                   |

> ⚠️ 官方明确强调：**发布、回退、下架等敏感操作权限不应分配给不相关人员。**

### 23.4 发布模式

| 模式               | 说明                         | 建议                                |
| ------------------ | ---------------------------- | ----------------------------------- |
| 全量发布           | 发布后所有用户访问都是新版本 | 普通小程序用这个                    |
| 分阶段发布（灰度） | 分时间段逐步放量             | 用户量大 / 功能变更大时用，控制风险 |

**紧急回退**：版本管理 → 线上版本 → 回退到上一个版本（需有"开发管理"权限）。

### 23.5 审核常见被拒原因（提前规避）

| 原因                            | 规避                                                               |
| ------------------------------- | ------------------------------------------------------------------ |
| 类目与内容不符                  | 上线前核对服务类目；涉及特殊行业需资质（医疗、金融、教育、直播等） |
| 未配置隐私保护指引              | 必配，且 `app.json` 开启 `__usePrivacyCheck__` 并适配              |
| 测试账号无法登录 / 功能无法体验 | 提交审核时填可用的测试账号与明确的功能路径                         |
| 诱导分享 / 诱导关注             | 去掉"分享得奖励"类文案                                             |
| 虚拟支付用了普通支付（iOS）     | iOS 虚拟商品改用 `wx.requestVirtualPayment`                        |
| 强制索取手机号 / 权限           | 去掉非必要的强制授权，改为按需                                     |
| 内容涉及违规                    | 用 `msgSecCheck` / `imgSecCheck` 做内容安全检测                    |
| 页面存在明显 bug / 白屏         | 提交前真机全量回归                                                 |
| 小程序名称/简介含敏感词         | 检查                                                               |
| 实际功能与描述不符              | 描述要准确                                                         |

### 23.6 上线前检查清单（Checklist）

```text
□ 真机（iOS + Android，至少各一台主流机型）全量功能回归
□ 体验评分（Audits）跑过，无明显性能问题
□ 主包 ≤ 2MB，分包配置正确，tabBar 页在主包
□ 服务器域名已配置且关闭「不校验域名」后仍能正常请求
□ 业务域名已配置（有 web-view 时）
□ 隐私保护指引已配置并生效，隐私接口已适配
□ 登录流程：冷启动 / 热启动 / session 过期 / token 过期 均正常
□ 授权：首次授权、已授权、已拒绝三种路径均验证
□ 支付：下单 / 取消 / 成功 / 失败 / 重复回调 / 退款 全链路验证
□ 订阅消息：订阅、下发、拒绝场景验证
□ 错误监控接入（onError + 实时日志 + 自建上报）
□ 版本号与备注填写正确
□ 测试账号与功能路径准备完毕
□ 关闭 debug 模式，移除 console 噪音（或保留必要日志）
□ 生产环境 API 地址正确（别把测试环境地址打包上去）
□ 小程序码 / 分享链接已生成验证
```

### 23.7 上线后

- **运营数据**：小程序后台 → 数据分析；或使用「we 分析」(https://wedata.weixin.qq.com)。
- **实时日志**：`wx.getRealtimeLogManager()`，可在后台查看用户侧日志，排查线上问题。
- **错误监控**：`App.onError` + `wx.onUnhandledRejection` + 服务端日志。
- **小程序码**：后台可预览下载 `wxacode.getUnlimited`（数量无限制，`scene` 最长 32 字符）。

## 二十四、常见坑速查表

| #   | 现象                                    | 根因                                                                               | 解决                                      |
| --- | --------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| 1   | 页面白屏                                | `pages` 没配 / 路径写错 / 文件缺失                                                 | 检查 `app.json` 的 `pages` 与文件路径     |
| 2   | 请求失败 `url not in domain list`       | 服务器域名未配置                                                                   | 后台配置；开发期临时勾选"不校验域名"      |
| 3   | 配了域名但请求 `xxx:443` 失败           | 域名配置带了/没带端口，URL 必须一致                                                | 要么都带端口，要么都不带                  |
| 4   | 开调试能请求，关调试不能                | 域名/证书问题                                                                      | 检查 HTTPS 证书信任链完整性               |
| 5   | `success` 里拿到 500 数据               | `success` 只表示收到响应                                                           | 自己判断 `res.statusCode`                 |
| 6   | 列表更新后视图不刷新 / 输入框串位       | 没写 `wx:key`                                                                      | 加 `wx:key`                               |
| 7   | `e.target.dataset` 取不到               | 点到了子元素                                                                       | 改用 `e.currentTarget.dataset`            |
| 8   | `setData` 报错超限                      | 单次数据 > 1MB                                                                     | 路径更新 / 分片 / 放 `this`               |
| 9   | 页面返回后数据不刷新                    | `onLoad` 不再次触发                                                                | 逻辑写 `onShow`                           |
| 10  | 热启动后初始化没执行                    | 只写了 `onLaunch`                                                                  | 需要每次执行的写 `onShow`                 |
| 11  | `navigateTo` 失败 `webview count limit` | 页面栈超 10 层                                                                     | 用 `redirectTo` / `reLaunch`              |
| 12  | `switchTab` 带参数丢失                  | `switchTab` 的 url 不支持参数                                                      | 用 storage / 全局变量 / 改 `reLaunch`     |
| 13  | 定时器/监听泄漏                         | `detached` / `onUnload` 没清理                                                     | 对称清理                                  |
| 14  | 位置授权弹窗不出现                      | `app.json` 未配 `permission`                                                       | 配置 `permission.scope.userLocation.desc` |
| 15  | 隐私接口（位置/头像）突然失效           | 未配置隐私保护指引                                                                 | 后台配置 + `__usePrivacyCheck__` 适配     |
| 16  | `code2Session` 返回 `40029`             | code 已用过/过期/非本小程序                                                        | 每次重新 `wx.login`，code 只用一次        |
| 17  | 拿不到 `unionid`                        | 小程序未绑定开放平台账号                                                           | 开放平台 → 绑定关系 → 小程序              |
| 18  | 用 openid 打通多端串号                  | openid 换 appid 就变                                                               | 用 unionid                                |
| 19  | `wx.authorize` 不再弹窗                 | 用户已拒绝过                                                                       | 引导 `wx.openSetting`                     |
| 20  | `getPhoneNumber` 的 code 换手机号失败   | 混用了 `wx.login` 的 code                                                          | 两者不同，不通用                          |
| 21  | 手机号额度突然扣费                      | 1000 次体验额度用尽（含开发版/体验版）                                             | 测试节制 / 购买资源包                     |
| 22  | 支付签名失败                            | 签名串缺末尾 `\n` / `timeStamp` 传数字 / `package` 值没前缀 / `appId` 写成 `appid` | 逐项核对                                  |
| 23  | 支付前端 success 但订单未支付           | 前端回调不可信                                                                     | 以服务端回调 + 主动查单为准               |
| 24  | 重复发货                                | 回调未做幂等                                                                       | `out_trade_no` 去重 + 事务                |
| 25  | 回调收不到                              | `notify_url` 非 HTTPS / 带 `?` / 超时                                              | 检查并 5 秒内返回 SUCCESS                 |
| 26  | 主包体积莫名变大                        | 未声明的目录被打进主包                                                             | 检查 `subPackages` 配置，用依赖分析       |
| 27  | tabBar 页放分包报错                     | tabBar 必须在主包                                                                  | 移回主包                                  |
| 28  | 分包互相 require 失败                   | 分包间不能互相引用                                                                 | 提到主包 或 用分包异步化                  |
| 29  | 独立分包 `getApp()` 为 undefined        | 主包未加载                                                                         | `getApp({ allowDefault: true })`          |
| 30  | 新 API 报 `is not a function`           | 低版本基础库不支持                                                                 | `wx.canIUse` / 判空降级                   |
| 31  | 上传代码失败，包超限                    | 超过 2MB                                                                           | 分包 + 资源上 CDN                         |
| 32  | 审核被拒（虚拟支付）                    | iOS 虚拟商品用了普通支付                                                           | 改用 `wx.requestVirtualPayment`           |
| 33  | `getStorageSync` 拿到 `''`              | 不存在的 key 返回空字符串                                                          | 判空用 `if (!v)`                          |
| 34  | 样式不生效（组件/页面）                 | 样式隔离                                                                           | `styleIsolation` / `externalClasses`      |
| 35  | 1px 边框消失/变粗                       | 用了 rpx                                                                           | 边框用 `px`                               |

### 25.3 三条最重要的心智模型

1. **双线程决定了所有性能问题**：任何"逻辑层 ↔ 视图层"的数据传输都有成本，`setData` 是核心瓶颈，能少传就少传。
2. **一切敏感操作都在服务端**：AppSecret、session_key、支付签名、支付回调、订单状态，全部在服务端。前端只负责 `wx.login` 拿 code、调起支付、展示结果。
3. **前端的一切结果都不可信**：`requestPayment:success` 不代表支付成功，前端传的 openid 可以伪造。以服务端回调/查单为准，以服务端按 token 反查的 openid 为准。
